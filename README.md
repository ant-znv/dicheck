# DI_Check

Локальное веб-приложение для проверки должностных инструкций (ДИ) через LLM API (DeepSeek, z.ai). Проверка выполняется по методике госконтракта (44-ФЗ/223-ФЗ, ТК РФ): приложение анализирует ДИ, формирует отчёт с правками и может исправить документ.

## Возможности

- Загрузка ДИ в форматах `.docx`, `.doc`, `.pdf`, `.txt`, `.md`, `.odt` — по одному файлу или пакетом (до 20 файлов, до 20 МБ каждый).
- Контекст госконтракта: предмет, тип занятости (полная/частичная), дополнительные условия.
- Проверка по системному промту на основе методики госконтракта (44-ФЗ/223-ФЗ, ТК РФ); промт редактируемый, есть вариант по умолчанию.
- Отчёт прямо в UI с итоговой оценкой (ок / риск / несоответствие) и структурированными правками «Было» / «Будет» с обоснованием.
- Экспорт отчёта в Markdown, HTML и DOCX.
- Исправление ДИ: детерминированное применение правок в исходный `.docx` с сохранением форматирования; если правку нельзя применить автоматически — LLM-фолбэк.
- Пакетное «Исправить все» — исправленные документы скачиваются одним zip-архивом.
- Отмена запущенной проверки, восстановление последней проверки после обновления страницы (F5).
- Выбор провайдера (DeepSeek / z.ai) и модели, проверка соединения.

## Быстрый старт

### Вариант A: портативная сборка (для конечного пользователя)

1. Распакуйте `DI_Check_portable.zip` в любую папку.
2. Запустите `DI_Check.exe` — браузер откроется сам на `http://127.0.0.1:8787`.

Python и Node.js на машине не нужны: фронтенд и промт встроены в exe.

Опции командной строки:
- `--port N` — запуск на другом порту;
- `--no-browser` — не открывать браузер автоматически.

Если порт уже занят (приложение уже запущено), exe просто откроет браузер на существующем экземпляре. Закрытие окна консоли останавливает сервер.

### Вариант B: из исходников (для разработчика)

Требования: Windows 10+, Python 3.12+, Node.js 20+.

1. Склонируйте репозиторий.
2. Запустите `start.bat` — он создаст виртуальное окружение `.venv`, установит зависимости, при первом запуске соберёт фронтенд, поднимет сервер на `http://127.0.0.1:8787` и откроет браузер.

Для старых файлов `.doc` нужен установленный Microsoft Word (используется Word COM).

## Настройка

В настройках приложения (UI):

- **API-ключ** — введите ключ выбранного провайдера. Ключи хранятся только локально, зашифрованными Windows DPAPI, в `%APPDATA%\DI_Check\config.json`.
- **Провайдер и модель** — DeepSeek или z.ai (GLM); можно проверить соединение и подгрузить список моделей.
- **Системный промт** — редактируемый; кнопка сброса возвращает промт по умолчанию (на основе `analiz-DI-goskontrakt-v4.docx`, раздел «2. Промт для ИИ»).

Приватность: всё работает локально, ключи никогда не покидают машину — они отправляются только в API выбранного провайдера при выполнении проверки. Через API приложения ключи не возвращаются (только флаг наличия ключа).

## Tesseract OCR (опционально)

Для сканированных PDF можно установить [Tesseract OCR](https://github.com/tesseract-ocr/tesseract) с языковыми пакетами `rus` + `eng`. Без него приложение корректно обработает текстовые PDF, а для сканов покажет подсказку об отсутствии OCR.

## Для разработчиков

### Структура репозитория

- `backend/app/` — FastAPI-бэкенд (порт 8787): `main.py` (endpoints, джобы проверок в памяти), `extractors.py` (извлечение текста из документов), `llm.py` (OpenAI-совместимый async-клиент на httpx), `settings.py` (конфиг в `%APPDATA%\DI_Check\config.json`, ключи шифруются DPAPI), `default_prompt.md` (промт по умолчанию).
- `frontend/` — React 19 + TypeScript + Vite 7 + Tailwind CSS v4; сборка в `frontend/dist`, раздаётся бэкендом как статика.
- `backend/testdata/` — тестовые ДИ, генераторы (`make_sample.py`, `make_samples_batch.py`) и сквозной тест `verify_batch.py`.
- `backend/tests/` — pytest-сьют бэкенда (LLM мокается, сеть/ключи/Word/Tesseract не нужны).
- `docs/api-contract.md` — контракт API фронтенд↔бэкенд; при изменении API обновлять его.

### Команды

| Действие | Команда |
|---|---|
| Запуск всего | `start.bat` |
| Бэкенд вручную | `.venv/Scripts/python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8787` |
| Тесты бэкенда | `.venv/Scripts/python.exe -X utf8 -m pytest backend/tests -q` |
| Сборка фронтенда | `cd frontend && npm run build` |
| Сборка портативного exe | `build_exe.bat` (запускает PyInstaller по `DI_Check.spec`) |

Сборка exe создаёт `dist\DI_Check\` (DI_Check.exe + `_internal`) и zip-архив `DI_Check_portable.zip`. В exe встроены фронтенд и промт.

Сквозной тест с реальным API-ключом (нужен запущенный сервер): `backend/testdata/verify_batch.py` — check → export docx → fix-all.

Примечание: при работе в консоли Windows вывод русского текста из Python — только в файл с `encoding='utf-8'` либо с `python -X utf8` (консоль cp1251 падает на `print`).

## Известные ограничения

- Джобы проверок живут в памяти процесса — после перезапуска сервера история недоступна (завершённые джобы хранятся до 24 ч или пока не наберётся 50 джоб).
- До 20 файлов на проверку и 20 МБ на файл; извлечённый текст длиннее 120 000 символов обрезается.
- Для файлов `.doc` (старый формат) необходим установленный Microsoft Word.
- Для сканированных PDF без установленного Tesseract OCR распознавание недоступно.
- Работает только на Windows (хранение ключей через DPAPI, Word COM, портативная сборка).
